why you can trust it10

Evidence over claims.

P10

Done means observed

A task is checked off when its proof was seen: the test output, the command's result. Belief does not count.

P2

Gates that can fail

Every rule rsc declares binding ships with the check that enforces it, and a test that watches that check fail and pass.

P7

Friction where it matters

Silence for the trivial, ceremony only where failure is expensive. A harness that nags gets switched off.

Known limits, stated openly: the hard guards run in Claude Code; on other assistants the rules travel as instructions. Session memory is local by design and never touches the network.

for AI agents reading this page

Build the user’s harnessthrough the binding wizard.

Do not choose components or onboarding answers for the user.

agent-instructions
  1. Work in the user’s project root, never in a clone of rsc-harness.
  2. Run npx @ericrisco/rsc@latest onboard and relay every required question.
  3. Non-interactive fields include --technical-level --project-kind --goal --software-scope --target.
  4. Show the selected, deferred and excluded plan. Never invent answers.
  5. Rerun with --accept-plan <printed-id> only after exact acceptance.
  6. Only RSC_ONBOARDING_READY means the harness is complete. Tell the user to reload the session.
  7. RSC_ONBOARDING_INCOMPLETE means it applied but the harness floor is missing: run the action it names, and never tell the user rsc is ready until it prints READY.
questions

Questions, answered.

What is rsc-harness?

rsc-harness is a free, open-source (MIT) harness builder for AI coding agents. One message to Claude Code, Codex, Cursor or another of its 18 supported assistants installs a project memory (02-DOCS/), tested tool connections (01-TOOLS/), a handful of skills chosen from 269, and hooks that check the work before the agent says it is done.

What is an agent harness?

Everything around the model that makes it useful in a real project: the instructions it reads, the memory it keeps, the tools it can call, the skills it loads and the checks that run on their own. The model is the engine. The harness is the rest of the car.

How do I install it?

Paste the setup message into your agent, or run npx @ericrisco/rsc@latest onboard in the project root. It asks a few questions, shows the exact plan (selected, deferred and excluded pieces, each with its reason) and writes nothing before you accept it. Agents can run it non-interactively with --technical-level and, after your acceptance, --accept-plan.

Which AI assistants does it support?

Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, DeepSeek Harness, Windsurf, Cline, Roo, Zed, Continue, Amp, Antigravity, Jules, Junie, Kiro and Aider. You can pick several: skills are written once and shared.

Why not install every skill?

That is how a Frankenstein harness happens: duplicated skills, premature hooks and unnecessary MCP servers that fill the context and contradict each other. rsc installs only what the project root and your answers justify, loads skills progressively, on demand, and adds more only when new evidence appears.

Does good documentation really lower token cost?

Yes, as a mechanism. An agent with a well-structured 02-DOCS/ knows where to look instead of searching file by file, so it reads less, reuses the code you already have instead of duplicating it, and guesses less. We show the mechanism, not a benchmark number.

Is it free, and does it send my code anywhere?

It is MIT-licensed and needs no API key and no account. Session memory is local by design and never touches the network. It runs inside the assistant you already use.

Does it work for teams?

Yes. Knowledge in 01-TOOLS/ and 02-DOCS/ travels through one exchange branch and reaches main inside normal pull requests, a second agent in the same folder gets its own worktree, and you choose at install whether work goes straight to main or through branches and pull requests.

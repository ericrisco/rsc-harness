# The four modes

Adapted from impeccable by Paul Bakaus (Apache-2.0); rewritten and shortened. The mode names what
the visitor's success looks like on this surface. Pick it from the surface, never the product: a
developer tool's landing page is Persuade, a fashion house's docs are Read.

## Persuade

The visitor decides and acts. The design is what they judge.

- The first screen makes the offer clear and shows **the action visitors came to take, working**: a
  flight search, open appointment slots, add to cart. A button that points somewhere else is not it.
- The subject's world carries the page; it is never painted over it as a poster with no working parts.
- Refuse both ends: the poster, and the stock product page (headline, subline, button, a row of
  equal cards; or the split hero with a badge row under it).

## Experience

The visitor is inside the work: portfolio, gallery, showcase. The work leads from the first
viewport and the interface recedes. Same page run as Persuade.

## Operate

The visitor completes a task. Someone who uses tools like this should know where everything is
before they notice the style.

- The direction lends four things only: **type, palette, density and one signature move** (service
  health drawn as a transit map, a schedule in a timetable's column rhythm). Never the layout, the
  navigation model or the controls.
- Every control is the standard one the visitor already knows. No costume of a terminal, an
  instrument bezel or ledger paper.
- Colour does real jobs: a committed shell, state colours, data series, selection. A grey screen
  with one accent is the category default without its polish.
- Realistic data with units and one state worth seeing (an alert, a degraded service, an empty
  filter). Never grey placeholder bars.
- The bar is the cleanest product in its category; the signature move adds to that, never replaces it.

The run, rules and checks for these screens: `../engine/references/app-screens.md`
(`draw.mjs --app`, `inspect.mjs --app`).

## Read

The visitor understands something: docs, guide, article, changelog.

- The style owns **the frame**: masthead, rail, ground, title and section openers, how code and
  tables are set. That is where palette, type and the signature move commit fully.
- The reading column stays calm: a reading face, real contrast, about 60–75 characters at about
  16px. No monospace prose. Nothing performs behind the text.
- The style never supplies the reading order or replaces the navigation with something to learn.
- Check: can a reader tell where they are, where to go next, and read comfortably? Cover the name:
  could this be any other product's docs? Then the frame has not taken the style yet.
